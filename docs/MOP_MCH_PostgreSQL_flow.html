MOP — MCH Preventive Healthcare Platform

Field-officer অ্যাকাউন্ট তৈরি, mother/child নিবন্ধন ও clinical visit — সবই PostgreSQL-এ (single source of truth), SQLite শুধু offline cache

Method of Procedure · সংস্করণ 1.0 · তারিখ 06 Jul 2026 · ব্রাঞ্চ claude/spring-boot-startup-error-d5igrb

স্থাপত্য (Architecture) সংক্ষেপে: Backend (Spring Boot) = লেখা ও পড়ার একমাত্র কর্তৃত্ব (system of record) → PostgreSQL। মোবাইল অ্যাপের লোকাল SQLite শুধু cache — অনলাইনে সার্ভার থেকে রিফ্রেশ হয়, অফলাইনে পড়ার জন্য fallback দেয়। Risk/nutrition শ্রেণিবিন্যাস (classification) সার্ভারে হয়, তাই অ্যাপ ও পোর্টাল সবসময় একমত।

1 · সিস্টেম ডেটা-ফ্লো (Read-through + Write-through)

Field Officer App Flutter (Android) Register / Visit Admin Portal Supervisor view Onboard officer SQLite cache offline read fallback only Spring Boot API /api/beneficiaries /api/workers Risk / MUAC classify PostgreSQL users beneficiaries ① write (POST) — Postgres authoritative ② persist ③ refresh cache ④ read onboard (POST /api/workers)
পর্যায়কী ঘটে
① Writeঅ্যাপ/পোর্টাল সরাসরি backend-এ POST করে (নিবন্ধন, visit, onboard)। PostgreSQL-ই কর্তৃত্ব।
② PersistBackend রেকর্ড PostgreSQL-এ সেভ করে এবং risk/MUAC সার্ভার-সাইডে শ্রেণিবিন্যাস করে।
③ Refresh cacheসার্ভারের authoritative রেকর্ড দিয়ে লোকাল SQLite cache আপডেট হয়।
④ ReadUI cache থেকে পড়ে; অনলাইনে প্রতিটি লোড আগে backend থেকে রিফ্রেশ হয়, অফলাইনে cache fallback।

4 · Field Officer — mother/child নিবন্ধন ও visit

ধাপকাজ
4.1Field (app) ভিউতে অংশ 3-এর credentials দিয়ে লগইন (POST /api/auth/login, PostgreSQL যাচাই)
4.2New registration → ফর্ম পূরণ → Save & start first ANC visit → POST /api/beneficiaries → PostgreSQL-এ নতুন beneficiary
4.3ANC visit: vitals দিন → Save → POST /api/beneficiaries/{id}/anc-visit → সার্ভার risk classify করে beneficiary আপডেট করে
4.4Child assessment: MUAC/edema দিন → Save → POST /api/beneficiaries/{id}/child-assessment → সার্ভার SAM/MAM নির্ণয় করে আপডেট করে

6 · Optimization — কেন এই ডিজাইন, ও পরবর্তী উন্নতি

যা এখন কার্যকর

  • SoT লেখা ও পড়া দুটোই PostgreSQL-কেন্দ্রিক — একটাই সত্য উৎস।
  • Cache SQLite শুধু cache: অনলাইনে সার্ভার থেকে রিফ্রেশ, অফলাইনে fallback।
  • Server classify risk/MUAC সার্ভারে নির্ণীত — অ্যাপ ও পোর্টাল কখনো ভিন্ন ফল দেয় না।
  • Consistency Admin যে credential দেখেন হুবহু তা-ই DB-তে; login ব্যর্থ হয় না।

পরবর্তী optimization (roadmap)

  • ETag / updated_at delta sync: পুরো তালিকা নয়, শুধু পরিবর্তিত রেকর্ড টানুন — ডেটা খরচ কমে।
  • Durable offline write-queue: অফলাইনে করা নিবন্ধন/visit payload-সহ কিউতে রেখে অনলাইনে সত্যিকারের endpoint-এ replay (শুধু ack নয়)।
  • Password hashing (BCrypt) + first-login reset ও JWT/session টোকেন।
  • Pagination + server-side filter (union/risk) বড় রেজিস্টারে দ্রুত লোড।
  • Optimistic UI: সার্ভার-রেসপন্সের আগে সাময়িক প্রদর্শন, ব্যর্থ হলে rollback।
  • Connection retry/backoff ও background sync worker।
Read/Write ডিজাইন নীতি: "Cache-aside" প্যাটার্ন — পড়ার সময় আগে সার্ভার (miss হলে cache), লেখার সময় সার্ভারে write-through করে তারপর cache আপডেট। এটি single-source-of-truth রক্ষা করে, আবার গ্রামীণ কম-সংযোগ পরিবেশে (যেমন Char Bhola) অফলাইন পড়াও সচল রাখে।
